# Our Server — сайт Minecraft-сервера

Официальный сайт сервера `mc.vin-off.site` (Paper, Minecraft 1.21.11). Человек, который впервые зашёл на сайт, за пару
минут узнаёт, работает ли сервер, скачивает [наш лаунчер](https://github.com/LIDFC/MkeiitLauncher) и заходит в игру.

- **Главная** — живой статус сервера (онлайн, игроки, версия, отклик), адрес с копированием, кнопка загрузки лаунчера под
  систему посетителя, превью карты, доска почёта, онлайн за сутки.
- **Лаунчер** — зачем он нужен, все сборки из последнего релиза GitHub с объяснением различий, пошаговая инструкция.
- **Карта** — squaremap во встроенном окне; пока карта не настроена, сайт честно об этом пишет.
- **Статистика** — итоги сервера, доски почёта, «кто был первым», график онлайна за 24 часа и 7 дней, таблица игроков.
- **Галерея** — постройки со скриншотом, автором, координатами и кнопкой «Показать на карте».
- **Правила** — правила и частые вопросы: AuthMe, Simple Voice Chat, подключение, лаунчер.
- **Аккаунт** — регистрация по коду приглашения, вход и профиль с ником Minecraft.
- **Скины** — игрок загружает свой скин, сайт проверяет и хранит его, выдаёт постоянную ссылку и готовую команду для
  SkinsRestorer. Скин принадлежит аккаунту, а не нику.

Все данные настоящие: статус спрашивается у Minecraft-сервера, статистика читается из файлов мира, версия лаунчера — из GitHub
API. Если источник недоступен, сайт так и пишет, а не показывает выдуманные цифры.

## Превью

Дизайн «глубинный сланец и фонарь»: графитовый фон, один тёплый янтарный акцент, зелёный — только для статуса «в сети».
Панель статуса на главной светится, как фонарь, и чем больше людей на сервере, тем ярче. Шрифты Onest и JetBrains Mono
(только для адреса, команд и координат) хранятся на самом сайте.

Чтобы посмотреть сайт с демо-данными, выполните шаги из раздела «Запуск локально».

## Стек

| Часть | Что | Почему |
|---|---|---|
| Фронтенд | [Astro](https://astro.build) 7, статическая сборка, TypeScript без фреймворка | готовый HTML, на странице один небольшой скрипт; никакого React ради пары виджетов |
| Бэкенд | Node.js 24, встроенный `http`, **ни одной runtime-зависимости** | около 70 МБ памяти; Node 24 запускает TypeScript сам, без шага сборки |
| Данные | файлы мира Minecraft, JSON-файл истории онлайна | для 10 игроков отдельная СУБД не нужна |
| Аккаунты | SQLite через встроенный `node:sqlite`, пароли — `scrypt` из `node:crypto` | уникальность логина и ника обеспечивает база; зависимостей по-прежнему ноль |
| Картинки | свои декодеры PNG и JPEG на TypeScript (`server/src/images/`) | скин весит килобайты, а sharp тянет нативную библиотеку и десятки мегабайт памяти на VPS с Minecraft |
| Карта | squaremap (плагин Paper) | заметно легче BlueMap |
| Прокси | nginx + Let's Encrypt | HTTPS, gzip, второй домен для карты |

## Запуск локально

Нужен Node.js 24 или новее.

```bash
npm ci
cp .env.example .env
node scripts/dev-fixtures.mjs
```

В `.env` для локальной проверки укажите:

```ini
TRUST_PROXY=false
MC_HOST=mc.vin-off.site          # живой статус настоящего сервера
MC_SERVER_DIR=.dev/minecraft     # демо-статистика из dev-fixtures
DATA_DIR=.dev/data
GALLERY_DIR=.dev/gallery
REGISTER_INVITE_CODE=dev-invite-code   # без кода регистрация закрыта
COOKIE_SECURE=false                    # локально нет https
```

`scripts/dev-fixtures.mjs` создаёт в `.dev/` вымышленных игроков, историю онлайна и картинки галереи. Эта папка игнорируется
git и на сервере не используется.

- `npm run dev` — сервер API на `:3000` и Astro с горячей перезагрузкой на http://127.0.0.1:4321 (запросы `/api` и `/media`
  проксируются на API);
- `npm run build && npm start` — production-режим на http://127.0.0.1:3000, как на VPS.

## Аккаунты

Аккаунт нужен только для одного: чтобы скины принадлежали игроку, а не нику.

- **Регистрация по коду.** `REGISTER_INVITE_CODE` в `.env` — общий код приглашения; пустое значение закрывает
  регистрацию совсем. Код меняется без пересборки, на существующие аккаунты это не влияет.
- **Вход по логину**, без email. Пароли хранятся как `scrypt`-хеш с солью, в ответы API не попадают никогда.
- **Сессия** — случайный токен в cookie `os_session` (`HttpOnly`, `SameSite=Lax`, `Secure` при `COOKIE_SECURE=true`).
  В базе лежит только SHA-256 этого токена, в `localStorage` — ничего. Каждое посещение продлевает срок
  (`SESSION_TTL_DAYS`, по умолчанию 30 дней).
- **Владелец — `users.id`.** Ник Minecraft можно менять в профиле: всё, что привязано к аккаунту, остаётся на месте.
  Ник и логин уникальны независимо от регистра — это `UNIQUE`-индексы в базе.
- **База** — `<DATA_DIR>/site.db` (SQLite). Миграции применяются сами при старте сервера, отдельной команды нет.
  Файл попадает в резервную копию вместе с `data/`.
- **Защита от подбора** — `AUTH_RATE_LIMIT_*` (по умолчанию 10 попыток за 15 минут) считается и по адресу, и по логину.
  Неверный логин и неверный пароль дают один и тот же ответ, поэтому перечислить аккаунты нельзя.

Администрирование из терминала (пароли не печатаются и не попадают в историю команд):

```bash
npm run users list
npm run users create Lev LevPlays
npm run users set-password Lev      # это же и сброс забытого пароля
npm run users set-nick Lev LevTheBuilder
npm run users logout-all Lev
npm run users delete Lev
```

## Скины

Страница «Скины» — личное хранилище одного скина на аккаунт.

- **Проверка файла.** Принимаются PNG и JPG/JPEG до 8 МБ. Тип определяется по сигнатуре файла, а не по расширению и не по
  заголовку запроса; расширение и заявленный тип должны совпадать с содержимым. Размер текстуры берётся из заголовка
  картинки **до** распаковки, поэтому «бомба» из десяти пикселей в гигабайт отсекается сразу. Разрешены только 64×64 и
  64×32. GIF, WebP, SVG, BMP, TIFF, архивы, программы и документы отклоняются с понятным текстом.
- **Всё пересохраняется.** Файл декодируется и записывается заново как 8-битный RGBA PNG без метаданных: на диск никогда
  не попадает ни одного байта исходного файла. JPG действительно конвертируется, а не переименовывается, — SkinsRestorer
  ждёт PNG-текстуру.
- **Имена файлов.** `<32 hex>.png` из `crypto.randomBytes`. Имя из браузера сохраняется только для показа и никогда не
  участвует в построении пути. Публичный адрес `/skins/<имя>.png` отдаётся с `image/png` и вечным кешем; каталог не
  листается, а всё, что не совпало с шаблоном имени, отвечает 404.
- **Один скин на аккаунт.** Новая загрузка заменяет предыдущую: сначала пишется новый файл, потом обновляется запись в
  базе, и только после этого удаляется старый файл (и то лишь если на него больше никто не ссылается). Если запись в базу
  не удалась, новый файл убирается, а прежний скин продолжает работать.
- **Владение.** В API нет ни идентификатора скина, ни идентификатора аккаунта: сервер всегда берёт владельца из cookie
  сессии, поэтому чужой скин недостижим ни по URL, ни подменой полей в запросе.
- **Лимиты.** `SKIN_UPLOAD_LIMIT_*` — не больше 10 загрузок за 10 минут с адреса, `SKIN_UPLOAD_COOLDOWN_SECONDS` — пауза
  между двумя загрузками одного аккаунта.
- **Имя скина.** По умолчанию — ник игрока в нижнем регистре (`levplays`), занят — `levplays2`, и лишь в крайнем случае
  шесть случайных символов. Игрок может поменять имя на любое свободное: 3–16 символов `[a-z0-9_]`. Слова, которые
  SkinsRestorer понимает как подкоманды (`clear`, `set`, `random`…), запрещены, уникальность держит индекс в базе. Имя
  остаётся за аккаунтом и переживает загрузку нового файла.
- **SkinsRestorer.** Сайт не выполняет команды на сервере и не имеет доступа к консоли. Он показывает готовую строку
  `/sr createcustom <имя> "https://…"`, дальше в игре `/skin set <имя>`.
- **Синхронизация из игры.** Когда игрок делает `/skin clear`, плагин
  [our-server-plugin](https://github.com/LIDFC/our-server-plugin) сообщает об этом сайту, и сайт удаляет запись и файл
  скина. Аккаунт находится по Minecraft UUID: первый раз UUID сверяется с `usercache.json` самого сервера и
  запоминается в `users.minecraft_uuid`, дальше смена ника ничего не ломает. Запрос защищён токеном
  `MINECRAFT_API_TOKEN`, повторные вызовы безопасны.

## API

Все ответы — JSON, общий лимит запросов на IP. Данные сайта читаются через `GET`, аккаунтные действия — через `POST`.

| Эндпоинт | Что отдаёт | Кеш |
|---|---|---|
| `GET /api/server/status` | онлайн, игроки, версия, отклик, время проверки | 15 с на сервере |
| `GET /api/server/players` | число игроков, максимум и ники (Server List Ping отдаёт до 12) | 15 с |
| `GET /api/server/stats` | статистика каждого игрока, итоги, «кто был первым» | 5 мин |
| `GET /api/server/leaderboard` | топ-5 по категориям и события мира | 5 мин |
| `GET /api/server/online-history?hours=24` | точки `[время, игроки]`, `-1` — сервер был выключен; `hours` от 1 до 168 | — |
| `GET /api/gallery` | постройки галереи | до изменения файла |
| `GET /api/launcher/release` | последний релиз лаунчера с разобранными сборками | 10 мин |
| `GET /api/config` | публичные настройки: адрес, ссылка на карту | — |
| `GET /api/health` | `{ "ok": true }` для мониторинга | — |
| `POST /api/auth/register` | создаёт аккаунт по коду приглашения, ставит cookie сессии → `201 { user }` | — |
| `POST /api/auth/login` | вход → `200 { user }`, неверные данные → `401 invalid-credentials` | — |
| `POST /api/auth/logout` | закрывает сессию и стирает cookie → `204` | — |
| `GET /api/auth/me` | текущий аккаунт → `200 { user }`, без входа → `401` | — |
| `POST /api/auth/profile` | меняет ник Minecraft → `200 { user }`, занятый ник → `409` | — |
| `POST /api/auth/password` | меняет пароль и закрывает остальные сессии → `204` | — |
| `GET /api/skins/me` | скин текущего аккаунта, ник и ограничения загрузки; без входа → `401` | — |
| `POST /api/skins` | загрузка: тело — сам файл, `Content-Type: image/png` или `image/jpeg` → `201 { skin }` | — |
| `POST /api/skins/name` | меняет имя скина для `/skin set` → `200 { skin }`, занято → `409` | — |
| `POST /api/skins/delete` | убирает скин и файл → `204`, скина нет → `404` | — |
| `POST /api/internal/minecraft/skin-cleared` | только для Minecraft-сервера: `Authorization: Bearer <MINECRAFT_API_TOKEN>`, тело `{ minecraftUuid, minecraftUsername? }` → `200 { success, deleted, reason? }` | — |
| `GET /skins/<имя>.png` | сам файл скина, `image/png`, кеш навсегда | 1 год в браузере |

Абсолютные пути сервера, UUID игроков и токены в ответы не попадают. `POST` принимается только с `Content-Type:
application/json` и только с этого же сайта (проверка `Origin`), тело — не больше 2 КБ. Аккаунт всегда берётся из cookie:
идентификатора пользователя нет ни в одном запросе, поэтому чужой профиль недостижим по определению.

## На будущее

- **Админка галереи.** Галерея читается через интерфейс `GalleryStore` (`server/src/services/gallery.ts`). Хранилище с
  загрузкой через панель — это вторая реализация того же интерфейса, страницы менять не придётся.
- **Новые категории статистики** добавляются одной строкой в `LEADERBOARD` и `MILESTONES` (`server/src/services/stats.ts`).
- **Полный список игроков.** Если на сервере включить `enable-query`, его можно добавить в `services/status.ts` — формат
  ответа API уже различает полный и частичный список (`playerListComplete`).
- **История скинов.** Сейчас у аккаунта один скин (`skins.user_id UNIQUE`). Если понадобится история, снимается
  уникальность и добавляется признак активного скина — остальная логика уже работает через `users.id`.
